# پراپ‌بین | Propbin

**پلتفرم فارسی بررسی، مقایسه و معرفی شرکت‌های پراپ تریدینگ**

پراپ‌بین یک وب‌سایت فارسی برای شناخت بهتر شرکت‌های پراپ تریدینگ، مقایسه امکانات و شرایط آن‌ها، مطالعه مطالب آموزشی و ثبت تجربه کاربران است. هدف پروژه، جمع‌آوری اطلاعات مرتبط در یک محیط یکپارچه است تا کاربران بتوانند گزینه‌های مختلف را ساده‌تر بررسی کنند و پیش از تصمیم‌گیری، شرایط هر شرکت را با دقت بیشتری مطالعه کنند.

**وب‌سایت اصلی:** [propbin.com](https://propbin.com)

> **سلب مسئولیت:** اطلاعات و امتیازهای سایت جنبه اطلاع‌رسانی دارند و توصیه سرمایه‌گذاری یا تضمین اعتبار، سودآوری و پرداخت شرکت‌ها محسوب نمی‌شوند. شرایط هر شرکت باید در مرجع رسمی آن بررسی شود.

## امکانات کاربران

- **صفحه اصلی:** معرفی خدمات و بخش‌های مهم وب‌سایت، نمایش محتوا و شرکت‌های منتخب.
- **بررسی شرکت‌ها:** فهرست شرکت‌های پراپ با صفحات جزئیات، قوانین، مشخصات و اطلاعات مرتبط.
- **مقایسه شرکت‌ها:** بررسی مشخصات چند شرکت در کنار یکدیگر.
- **کدهای تخفیف:** نمایش تخفیف‌ها و اطلاعات ثبت‌شده برای شرکت‌ها.
- **نظرسنجی و امتیازدهی:** ثبت تجربه، دیدگاه و امتیاز کاربران با امکان مدیریت و تأیید محتوای ارسالی.
- **مقالات:** نمایش مقالات و محتوای آموزشی با آدرس اختصاصی و فیلدهای مرتبط با سئو.
- **جست‌وجو:** جست‌وجوی محتوای سایت و شرکت‌ها.
- **حساب کاربری:** ثبت‌نام و ورود با جریان‌های احراز هویت موجود در پروژه و مشاهده اطلاعات حساب.
- **پشتیبانی:** ارسال پیام از حساب کاربری و پیگیری پاسخ‌ها.
- **قرعه‌کشی مقاله‌ای:** بخش جداگانه‌ای برای مشارکت و مدیریت قرعه‌کشی مرتبط با مقالات، مطابق تنظیمات مدیر.
- **همکاری:** صفحه معرفی راه‌های همکاری با وب‌سایت.

## فناوری‌ها و معماری

| لایه | فناوری |
|---|---|
| Full-stack Framework | Next.js 15 (App Router) |
| رابط کاربری | React 19 |
| زبان | TypeScript |
| استایل | Tailwind CSS 4 |
| آیکون‌ها | Lucide React |
| پایگاه داده | PostgreSQL 16/17 |
| اتصال دیتابیس | `pg` و لایه سازگاری داده در `lib/supabase-admin.ts` |
| Runtime پیشنهادی | Node.js 22 LTS |
| ایمیل | Nodemailer / تنظیمات سرویس ایمیل |
| فایل‌های آپلودی | دیسک پایدار VPS در `.uploads/` |
| استقرار پیشنهادی | Ubuntu + Nginx + Node.js + PostgreSQL |

در این معماری، صفحات و APIها در Next.js اجرا می‌شوند. اطلاعات ساخت‌یافته در PostgreSQL ذخیره می‌شود؛ فایل‌های بارگذاری‌شده در فضای ذخیره‌سازی دائمی سرور قرار می‌گیرند. برخی فایل‌های محتوایی پروژه نیز خارج از دیتابیس ذخیره می‌شوند و باید در برنامه پشتیبان‌گیری لحاظ شوند.

> **محدوده دیتابیس:** در نسخه فعلی تحویلی، جداول و منطق دیتابیس **گردونه شانس** عمداً حذف شده‌اند. **قرعه‌کشی مقاله‌ای** قابلیت مستقلی است و ساختار دیتابیس آن باقی مانده است.

## راه‌اندازی در محیط توسعه

### پیش‌نیازها

- Node.js 22 LTS
- npm
- PostgreSQL 16 یا 17
- دسترسی به نصب وابستگی‌ها از npm registry

### ۱. دریافت سورس و نصب وابستگی‌ها

```bash
git clone <REPOSITORY_URL>
cd <PROJECT_DIRECTORY>
npm ci
```

نشانی مخزن و نام پوشه را با مقادیر واقعی جایگزین کنید.

### ۲. ایجاد فایل تنظیمات

```bash
cp .env.example .env.local
```

نمونه متغیرهای اصلی:

```dotenv
DATABASE_URL=postgresql://propbin_app:YOUR_URL_ENCODED_PASSWORD@127.0.0.1:5432/propbin
NEXT_PUBLIC_SITE_URL=http://localhost:3000

ADMIN_PASSWORD=REPLACE_WITH_A_STRONG_PASSWORD
ADMIN_SESSION_SECRET=REPLACE_WITH_A_LONG_RANDOM_SECRET
USER_AUTH_SECRET=REPLACE_WITH_ANOTHER_LONG_RANDOM_SECRET

# در صورت استفاده از سرویس ایمیل:
RESEND_API_KEY=
MAIL_FROM=Propbin <login@your-verified-domain.com>
```

در سرور اصلی مقدار `NEXT_PUBLIC_SITE_URL` باید `https://propbin.com` باشد. متغیرها باید با تنظیمات واقعی سرویس ایمیل و احراز هویت هماهنگ شوند.

**هشدار:** `.env.local` و اطلاعات اتصال، رمزها و کلیدهای API را در Git قرار ندهید.

### ۳. ساخت دیتابیس

ابتدا دیتابیس و کاربر PostgreSQL را مطابق فایل `DATABASE-HANDOVER-FA.md` ایجاد کنید. سپس:

```bash
npm run db:setup
```

این دستور ساختار پایه و Migrationهای تعریف‌شده را اجرا می‌کند و وجود جداول و ستون‌های ضروری را بررسی می‌کند. داده‌های نمونه شرکت‌ها و مقالات به‌صورت خودکار وارد نمی‌شوند.

### ۴. اجرای سایت

```bash
npm run dev
```

آدرس محلی:

**http://localhost:3000**

## نصب دیتابیس PostgreSQL

برای نصب جدید و خالی، راهنمای کامل در فایل‌های زیر قرار دارد:

- `DATABASE-HANDOVER-FA.md`
- `POSTGRES-SETUP-FA.md`
- `DATABASE-HANDOVER-FA.pdf`

دستورات اصلی:

```bash
npm run db:migrate
npm run db:verify
```

آزمون تکمیلی در صورت نصب ابزار `psql`:

```bash
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f database/smoke-test.sql
```

**نکته:** جداول گردونه شانس در دیتابیس جدید ساخته نمی‌شوند؛ جداول قرعه‌کشی مقاله‌ای همچنان وجود دارند.

## استقرار روی VPS

پیکربندی پیشنهادی برای شروع کار:

- Ubuntu 24.04 LTS
- حداقل پیشنهادی عملیاتی: 4 vCPU، 8 GB RAM و 100 GB NVMe
- Node.js 22 LTS
- PostgreSQL 16/17
- Nginx به‌عنوان Reverse Proxy
- SSL/TLS با Let's Encrypt
- فضای ذخیره‌سازی پایدار برای `.uploads/`
- مدیریت دائمی پروسه با systemd یا PM2

پس از تنظیم محیط و دیتابیس:

```bash
npm ci
npm run db:setup
npm run check:types
npm run build
npm run start
```

مقادیر دامنه در محیط Production:

```dotenv
NEXT_PUBLIC_SITE_URL=https://propbin.com
```

نمونه رکوردهای DNS پس از دریافت IP واقعی سرور:

```text
A      @      <SERVER_PUBLIC_IP>
CNAME  www    propbin.com
```

برای تنظیم Nginx، SSL، بکاپ و الزامات سرور، فایل `DEPLOY-PRODUCTION-FA.md` را مطالعه کنید.

## امنیت و پشتیبان‌گیری

- فایل‌های `.env.local`، رمزها، کلیدهای API و اطلاعات دیتابیس را در Git Commit نکنید.
- برای دیتابیس از کاربر اختصاصی و دسترسی محدود استفاده کنید؛ پورت PostgreSQL را عمومی نکنید.
- در محیط عملیاتی، ورود آزمایشی (`DEV_MOCK_LOGIN`) را فعال نکنید.
- از HTTPS استفاده کنید و رمزهای اولیه را قبل از انتشار تعویض کنید.
- به‌صورت منظم از PostgreSQL، پوشه `.uploads/` و فایل `data/content.json` بکاپ تهیه کنید.
- بکاپ را خارج از همان VPS نگهداری کنید و فرآیند بازیابی را روی محیط آزمایشی بررسی کنید.
- از ارسال رمز کاربران و اطلاعات حساس در پیام‌های پشتیبانی یا گزارش خطا خودداری کنید.

نمونه تهیه بکاپ:

```bash
DATABASE_URL='postgresql://...' ./scripts/db-backup.sh
```

برای بازیابی، به فایل `DATABASE-HANDOVER-FA.md` مراجعه کنید. اجرای اسکریپت بازیابی می‌تواند اشیای دیتابیس مقصد را تغییر دهد یا جایگزین کند.

## وضعیت پروژه و محدودیت‌ها

این مخزن شامل سورس وب‌سایت و ابزارهای نصب دیتابیس است. قابلیت‌ها بر اساس مسیرها و ماژول‌های موجود در کد توضیح داده شده‌اند؛ فعال بودن کامل هر قابلیت به پیکربندی سرویس‌ها و آزمون عملی وابسته است.

- نصب دیتابیس جدید، **داده‌های دیتابیس قبلی را منتقل نمی‌کند**.
- دیتابیس جدید بدون داده محتوایی نمونه ساخته می‌شود؛ ردیف‌های تنظیماتی ضروری ایجاد می‌شوند.
- **گردونه شانس** در محدوده دیتابیس تحویلی وجود ندارد. **قرعه‌کشی مقاله‌ای** حفظ شده است.
- فایل‌های قدیمی روی سرویس‌های ذخیره‌سازی دیگر، در صورت وجود، خودکار به VPS منتقل نمی‌شوند.
- پیش از انتشار عمومی باید نصب وابستگی‌ها، Build، اتصال دیتابیس و مسیرهای اصلی سایت در محیط Staging تست شوند.
